# 3 分钟演示脚本（录屏用）

> 目的：让看的人 3 分钟内明白"这是什么、怎么用、结论是什么"。

## 0:00–0:20 问题

"很多界面对屏幕阅读器不友好，但没人量化过。这个工具用只读方式测：一个页面上有多少控件读不出来、
多少点击区太小、多少页面根本没有可操作节点。"

## 0:20–0:50 一条命令

```bash
python collectors/collect_batch.py --serial <SN>    # 26 页，约 1 分钟
python analyze/analyze.py data/lint.jsonl           # 出报告
```

画面：终端滚出每页一行指标 → 最后生成 `report.md` / `report.html`。

## 0:50–1:40 三个发现（讲"修正"而不是"数字"）

1. 第一版口径算出 90% 不可读 —— 错了，因为可点的是容器、文字在子节点
2. 改成看子树 → 10%；再发现开关的标签在**同级** TextView 上（`labelFor` 不导出）→ 0.8%
3. 最后换成**标签距离**分布：真实无标签 **0%**，但 **9.5% 依赖行标签**

一句话："每次数字变小，我都能说出为什么。"

## 1:40–2:20 数据源可信度

- 同页连采 8 次：节点数抖动 **0%**
- 单页 **1.86 秒** → 32 页/分钟
- 滚动会让指标抖 **±7%**，所以固定位置采样

## 2:20–2:50 边界

- 只读：不点、不输入、不提交
- 只存统计量：无界面文本（`privacy_scan.py` 在 CI 里强制）
- 端侧通道没做：判定门槛写在 `DECISIONS.md`

## 2:50–3:00 结尾

"这是一个 3 分钟能跑完、任何人都能复现的审计工具；
代码和实验记录都在仓库里，包括我算错的那几版。"
